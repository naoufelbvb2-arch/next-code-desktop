**APPROVED / NORMATIVE / FROZEN v1.0.** Prospective owner adoption under
P9-R03 Decision A, received 2026-11-10, approving CP-002 sections2–5 including
the currently advertised single model. This additive acceptance-profile

This is scope ratification, not runtime evidence, consent or product acceptance.

## 1. V1 product and invocation boundary

V1 supports Next Code AgentOS as its only Coding Engine and DeepSeek as its only
production LLM provider. Its current sole advertised model is `deepseek-flash`.
Additional production providers and local LLM inference are DEFERRED; a generic
multi-engine platform is OUT OF V1 SCOPE. Desktop and Engine remain independent
repositories with the existing thin private bridge. No Engine modification or
copying follows from this addendum.

Actual model calls continue through the original ModelGateway with independently
verified effective DeepSeek destination identity. Display labels and model names
are not provider authority. Persisted issued model/provider identity cannot be
reinterpreted by later preferences or configuration; active attempts never
retarget. Unsupported/unresolved routes or destination mismatch fail closed,
with no silent fallback, implicit retry or paid request authority.

## 2. Mandatory safety that is not deferred

Keep exact project/provider/disclosure-class challenge, consent and revocation
at the last Main-controlled release. No new consent is implied by the owner's
provider decision. Revocation stops future Main handoffs; it cannot recall
already released content or prove remote receipt/deletion. Wrong/changed class,
scope, unresolved provider or modified destination cannot inherit a grant.

All native containment, root identity, alias/TOCTOU, reparse/symlink/mount,
sensitive-content denial, resource bounds, evidence integrity, read-only
Discussion, explicit Run Task and process/lease proof requirements remain
mandatory. Keep synthetic independent provider tests as isolated negative/route
fixtures, never production routes, real local models or live provider proof.
No raw source/credential/process capability is added to Renderer.

## 4. Future DeepSeek models

Before advertising another DeepSeek model, obtain separately authorized
implementation and evidence for its exact ModelGateway route, effective provider
destination, model identity/capabilities/budgets/readiness, issuance immutability,
consent/class behavior, no fallback, negative isolation and actual compatibility.
Reinstate I06-T03's positive multi-model and I06-T04's positive UI-switch variants
before advertising the second model. A shared provider label is not evidence of
route equivalence. Additional providers/local inference require a separately
approved scope/architecture transition; none is authorized here.
